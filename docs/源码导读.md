⚠️ **重建版的已知不确定点**：

1. **`0x00–0x09` 的代码号是按 `Protocol_Dispatch` 的 switch 顺序推定的**（ARM=0x00 … SET_DEF=0x09）。
   `0x0A/0x0C/0x0F/0x20/0x21/0x22/0x30/0x8A` 有源码注释作证，可以放心。
   **若上位机侧（ROS 桥接）按别的编号写，必须两边对齐**——本文件是唯一定义处，改这里即可。
2. 帧中途出现 `0x68` **不当作新帧头**（数据区里合法会有 0x68，例如 INFO 文本里的 `h`），
   靠 sum/tail 不符或上层 20 ms 半帧超时复位。这是有意为之，自测里已固化该行为。
3. `CAR_PROTO_MAX_DATA` 取 **48**（要容纳 0x21 电机帧的 34 字节数据）；原版值未知，只要 ≥34 就不影响兼容。

**如果你能拿到原版 `include\` 目录（另一台机器 `F:\ros2\car\include`），直接覆盖这三个文件即可，不必以重建版为准。**

## 四、串口协议速查（v1.1.2）

帧格式 `0x68 | LEN | CODE | DATA[n] | SUM | 0x16`，`LEN=1+n`，`SUM=(CODE+DATA…)&0xFF`。

| CODE | 命令 | 说明 |
|---|---|---|
| 0x00 | ARM | 解除急停 |
| 0x01–0x04 | FORWARD / BACK / LEFT / RIGHT | 取绝对值；数据 0 用默认值；**AKM 下 LEFT/RIGHT 是前轮转角 mrad** |
| 0x05 | STOP | |
| 0x06/0x07 | SPIN_L / SPIN_R | 仅 vx==0 时允许 |
| 0x08 | VECTOR | 6 B：vx/vy/wz |
| 0x0A | QUERY | 由链路任务回 STATUS(0x8A) |
| 0x0B | ESTOP | 清 armed，需 0x00 恢复 |
| 0x0C | RAW | 直驱 PWM 调试 |
| 0x0D/0x0E | SET_TURN / SET_SPEED | |
| 0x0F | SET_TLM | 遥测位图（HB/MOT/DRIVE） |
| 0x20/0x21/0x22 | HB / MOT / DRIVE | 上行遥测 16 / 34 / 6 B |
| 0x30 | INFO | ASCII 文本（开机横幅） |

每条命令执行后立即回 ACK（同代码号 + 1 B `OK/FAIL`）。
串口 = **USART3，PD8=TX / PD9=RX，115200-8-N-1**。

## 六、已知问题（★ 优先级从高到低）

1. **JTAG 未关闭**：编码器 A/B 用到 PA15/PB3/PB4（JTAG 脚），全工程没有任何 SWJ 重映射代码
   → 复位后这两路编码器可能读不回数，PI 环退化成开环。建议在 `bsp_encoder.c` 初始化前加：
   `RCC_APB2PeriphClockCmd(RCC_APB2Periph_AFIO, ENABLE); GPIO_PinRemapConfig(GPIO_Remap_SWJ_JTAGDisable, ENABLE);`
   （保留 SWD，别用 `SWJ_Disable`）。
2. **`..\include\` 三个共享文件已重建（2026-11-22）** → 现在 0 错误 0 警告；但 `0x00–0x09` 代码号是推定值，见第三节。
3. **AKM 语义与 ROS `/cmd_vel` 不一致**：下位机把 `wz` 当前轮转角用（clamp 到 −0.49…0.32 rad），
   上位机必须自己换算 `steer = atan(L·ω/v)`，不能直传 `angular.z`。
4. `s_armed` 上电默认 1（可运动），只靠 PD3 硬件开关兜底，建议改默认 disarmed。
5. 固件报的串口是 USART3，而 AGENTS.md 记的是"USART1 预留 ROS"；C30D 的 CH9102 到底接哪一路 UART，需对原理图确认。

## 七、和车上固件的关系（★ 2026-11-22 用户确认）

**这份代码就是车上现在正在跑的底盘固件。** 所以：

- **串口协议以本工程为准**：`0x68 | LEN | CODE | DATA | SUM | 0x16`，115200-8-N-1，USART3（PD8=TX / PD9=RX）。
- 上位机不需要再猜下行帧 —— **代码号表就是协议规范**（见第四节），`0x00 ARM` / `0x06 SPIN_L` / `0x0D SET_SPEED` / `0x0E SET_TURN` 等直接可用；每条命令都会回 ACK（CODE 与命令相同 + 1 字节数据：**`0x00` 已执行 / `0xFF` 被拒**）。
- 开机时 INFO 帧会发 `car_driver v1.1.2` 横幅；`0x20/0x21/0x22` 三组遥测上电默认全开，接上串口就能看到周期帧。
- ⚠️ 旧的"24 字节 `0x7B … 0x7D` 上行帧"记录（`整车拓扑与上下位机_整理.md` 第十一节、`AGENTS.md` 第七节，2026-09-22 实测）**属于之前的固件，与本工程不符**，不要再据此解析。

## 九、怎么编译（命令行 / GUI）

本机实际在用的 Keil 是 **µVision 5.29**，装在 `F:\Program Files\Keil529\`（`RTEPATH="F:\KeilPack"`，F4 芯片包只有 **2.15.0**，够用）。
`D:\Keil_v5`（5.23）是另一套旧安装，与本工程无关。

```bash
# 全量重编（命令行，不弹窗）
"/f/Program Files/Keil529/UV4/UV4.exe" -r car_driver.uvprojx -j0 -o /tmp/uv.log
# 增量编译
"/f/Program Files/Keil529/UV4/UV4.exe" -b car_driver.uvprojx -j0 -o /tmp/uv.log
tail -5 /tmp/uv.log      # 期望 Program Size + 0 Error(s), 0 Warning(s)
```

- 产物落点：`.axf` / `.o` / `.d` / 编译日志进 **`_build_output\`**（`OutputDirectory` 已改）；
  但 **`car_driver.map` 与 `startup_stm32f40_41xxx.lst` 仍会被 Keil 写到工程根目录**（实测 `ListingPath` 对这两项无效），编完手动 `mv` 进 `_build_output\` 即可。
- `UV4.exe` 由 DSH 沙箱直接调用会返回 **exit 127**（权限限制），需要临时放宽权限才能跑。
- 每次命令行构建都会在工程根目录生成 `car_driver.uvguix.<当前 Windows 用户>` 窗口布局文件，属于正常现象。

**协议自测**（不接硬件，验证组帧/解析）：测试源码在 `..\..\..\_scratch\_proto_test\t.c`（本仓库），把 `include\` 三个文件和它一起用 gcc 编一遍即可：

```bash
gcc -std=c99 -Wall -Wextra -I. -o t.exe t.c car_protocol.c && ./t.exe   # 期望 ALL TESTS PASSED
```
